## 项目目标

本项目拟将分散的 AI 学术技能、原始法律资料检索、文献核验和论证审查过程整合为可复用、可组合、可维护的研究模块。主要服务于：

1. **法学课程与考试**：法律概念辨析、规范体系梳理、案例研读。
2. **学位论文与学术写作**：选题论证、文献综述、研究设计、引注审查。
3. **规范检索与比较法**：中国现行法、司法解释、域外立法和判例。
4. **知识产权与 AI 法律**：著作权、专利、平台责任、生成式 AI、RAG。
5. **实证法学研究**：问卷设计、案例编码、样本说明、统计复核。

项目不以“一键生成论文”代替独立研究，而是提高检索、验证、组织、论证与复核的效率。

## 设计原则

| 原则 | 要求 |
| --- | --- |
| 来源固定 | 记录上游仓库、作者、版本或 commit SHA、许可证与引入时间 |
| 原文优先 | 重要结论应能定位到法律、判决、论文或权威原始资料 |
| 事实与观点分离 | 区分法条、裁判认定、当事人主张、学界观点和 AI 推断 |
| 保留原有功能 | 新模块引入前检查冲突，更新后开展回归测试 |
| 最小权限 | 不默认执行不明脚本、读取密钥或上传研究材料 |
| 版本可复现 | 关键依赖版本锁定，重要改动保留变更记录 |
| 学术诚信 | 不编造文献、DOI、页码、案号、法律条文或研究数据 |
| 兼容性实测 | 区分“文件可读”与“技能可安装、可调用、可稳定运行” |

## 法律研究证据规范

### 来源优先级

法律规范与案件的核查应以对应法域、对应时点的权威原始来源为主。以下为检索入口，**入口不等于某一条法律规则已经核验**：

- [国家法律法规数据库](https://flk.npc.gov.cn/)
- [中国人大网](http://www.npc.gov.cn/)
- [最高人民法院](https://www.court.gov.cn/)
- [中国法院网](https://www.chinacourt.org/)
- [WIPO Lex](https://www.wipo.int/wipolex/)
- [EUR-Lex](https://eur-lex.europa.eu/)
- [英国立法数据库](https://www.legislation.gov.uk/)
- [美国 Congress.gov](https://www.congress.gov/)

对于修法、司法解释、废止或判决进展，应明确标注资料的**公布日期、施行日期、检索日期及适用的法律时点**；草案、征求意见稿与生效规范必须区分。

### 最小证据记录模板

| 字段 | 内容 |
| --- | --- |
| 待验证论断 | 具体、可检验的命题 |
| 原始来源 | 文件全称、发布机关/作者、出处链接 |
| 精确定位 | 条号、页码、段落、案号等 |
| 时间信息 | 发布、施行、访问及适用时点 |
| 信息类型 | 法律规范/裁判材料/研究文献/新闻/推断 |
| 核验状态 | 已核验/部分核验/未核验 |
| 适用限制 | 争议、证据缺口、法域和适用范围 |

### 禁止事项

- 不得伪造判决书、法律条文、文献、DOI、页码、调查样本或统计结果。
- 不得把当事人观点写成法院认定，或把 AI 推断写成确定法。
- 不得以二手报道或摘要直接替代关键原文。
- 无法检索、无法访问或未核实的材料，必须明确标注。

## 标准研究工作流

```text
明确研究问题、法域与研究时点
            ↓
建立关键词、资料范围和纳入/排除标准
            ↓
检索原始资料并记录出处、版本和定位
            ↓
核查真实性、效力、适用范围及重复材料
            ↓
提炼法律争点、理论分歧与证据缺口
            ↓
构造论证：主张 → 依据 → 推理 → 反例 → 限制
            ↓
复核引注、统计、概念、时间和结论强度
            ↓
形成成果，并保留复核清单
```

### 示例：RAG 与著作权研究

1. 将 RAG 拆分为知识库建立、内容切分及索引、检索、上下文拼接、模型输出等阶段。
2. 分别分析每一阶段可能涉及的作品利用行为，**不预设所有技术步骤都构成侵权**。
3. 核查适用法域的著作财产权、权利限制、责任主体和举证规则。
4. 归纳真实可查的司法案例，区别案件事实、双方主张与裁判结论。
5. 比较不同研究观点，并记录反例、政策考量与未决问题。
6. 输出有条件的研究结论及人工复核清单。

## 可直接使用的提示词

本节是**可人工复制的研究提示词**，并非已安装的 Skill：

```text
你是法学研究助理，负责检索思路、资料组织和论证审查，不代替研究者作最终判断。

研究主题：【填写】
适用法域：【填写】
法律与资料截止日期：【YYYY-MM-DD】
用途：【论文/课程/案例评析/其他】

请依次执行：
1. 拆分法律争点，说明关键概念及隐含前提。
2. 设计关键词、资料来源、纳入和排除标准。
3. 提供可核验的规范、裁判和学术文献来源；未核实的明确标记。
4. 严格区分法条、裁判认定、当事人主张、学者观点与模型推论。
5. 分别分析支持与反对的论证，寻找有意义的反例。
6. 输出“研究结论—证据—适用范围—不确定性”对照表。
7. 形成需要人工核对的清单。

不得编造法律、案号、书目、DOI、页码、链接或数据。
如无法访问原文，应明确说明，不得将记忆中的内容冒充实时检索。
```

## 第三方 Skills 收录规则

不建议把多个不明来源的 GitHub 项目直接复制到一个仓库。拟引入项目需依次核查：

1. 原作者、上游仓库及维护情况。
2. 许可证与再分发条件。
3. 明确版本号或 commit SHA。
4. 安装脚本、外部请求、密钥与敏感文件权限。
5. 与现有模块的重复、冲突及替代关系。
6. 在目标环境的加载、调用和失败场景。
7. 回归测试与可回滚方案。

建议登记格式：

```yaml
name: candidate-skill
upstream: https://github.com/OWNER/REPOSITORY
revision: "<待核实的 commit SHA>"
license: "<待核实的许可证>"
imported_at: "<YYYY-MM-DD>"
review_status: pending
tested_environments: []
changes_from_upstream: []
known_limitations: []
```

以上为格式示例，不代表该候选项目已被收录。
